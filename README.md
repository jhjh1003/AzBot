# LoL Helper Bot (AzBot)

AtoZ 롤(LoL) 클랜을 위한 디스코드 봇입니다. 클랜원들의 자유 랭크 전적을 모아서 **라인별
티어픽, 밴픽 추천, 승률 순위, 게임별 기여도 점수(AZ기여도)** 같은 클랜 자체 데이터 기반
통계를 슬래시 커맨드로 보여줍니다. Vultr 클라우드 VM에서 24시간 상시 가동 중입니다.

- **스택**: C# / .NET 10 (LTS) · Discord.Net 3.20.1 · SQLite · Riot Games API (Match-V5,
  Timeline) · Docker + GitHub Actions/GHCR + Vultr VPS
- **명령어 전체 목록**: 아래 5장("클랜 전적 통계") 참고, 한눈에 보는 요약 표는
  [ARCHITECTURE.md](ARCHITECTURE.md) 11절에도 있음
- **버전/변경 이력**: [CHANGELOG.md](CHANGELOG.md) — 기능을 추가하거나 기존 동작을 바꾸면 이
  파일도 같이 갱신해 주세요.
- **코드를 안 읽고 전체 구조부터 이해하고 싶다면**: [ARCHITECTURE.md](ARCHITECTURE.md) —
  폴더/파일별 역할, 동작 흐름, 배포 구조를 비유와 다이어그램으로 정리한 문서.
- **아직 안 한 것 / 다음에 할 것**: [AfterUpgrade.md](AfterUpgrade.md)
- **내 PC 없이 클라우드에서 24시간 돌리고 싶다면**: [DEPLOY.md](DEPLOY.md) — 처음부터
  다시 배포하는 전체 스텝바이스텝 가이드 (현재 Vultr 서울 리전 + GitHub Actions CI로 운영 중).

## 1. 필요한 값 준비

| 값 | 어디서 구하나 |
|---|---|
| Discord 봇 토큰 | Discord 개발자 포털 → 해당 애플리케이션 → Bot 탭 → Reset Token |
| Discord 서버(길드) ID | 디스코드 설정 → 고급 → 개발자 모드 ON → A to Z 서버 아이콘 우클릭 → "서버 ID 복사" |
| Riot API 키 | Riot 개발자 포털 대시보드의 테스트 키(24시간) 또는 승인된 Personal Key |

## 2. 값 주입 — user-secrets 방식 (권장)

`LolHelperBot` 폴더에서 아래 명령을 실행합니다. `dotnet user-secrets`는 값을 프로젝트 폴더 밖(사용자 프로필)에 저장하므로 실수로 git에 커밋될 걱정이 없습니다.

```powershell
cd LolHelperBot
dotnet user-secrets set "Discord:Token" "여기에_봇_토큰"
dotnet user-secrets set "Discord:GuildId" "여기에_서버_ID"
dotnet user-secrets set "Riot:ApiKey" "여기에_Riot_API_키"
```

### 대안: 환경변수 방식

PowerShell 세션에서 임시로 쓰고 싶다면:

```powershell
$env:Discord__Token = "여기에_봇_토큰"
$env:Discord__GuildId = "여기에_서버_ID"
$env:Riot__ApiKey = "여기에_Riot_API_키"
```

(이 방식은 터미널을 닫으면 값이 사라집니다. 계속 쓰려면 user-secrets나 OS 환경변수 설정을 이용하세요.)

**절대 `appsettings.json`에 실제 값을 직접 쓰지 마세요** — 이 파일은 커밋 대상입니다. 토큰/키 칸은 항상 빈 문자열로 유지합니다.

## 3. 실행

```powershell
cd LolHelperBot
dotnet run
```

콘솔에 `[준비 완료] 길드 ... 에 슬래시 커맨드를 등록했습니다.`가 뜨면 성공입니다. 디스코드 A to Z 서버에서 `/ping`, `/riotcheck`를 입력해서 응답을 확인하세요.

- `/ping` → "🏓 pong! ..." 응답이 오면 디스코드 연결 OK.
- `/riotcheck` → "✅ Riot API 연결 성공 ..." 이 오면 Riot API 키 OK. "❌"가 뜨면 메시지에 원인이 나옵니다(키 만료 등).

## 4. AtoZ 멤버 등록

Discord에서 `/atoz 멤버등록`을 선택하고 `롤아이디` 입력란에 Riot ID를 입력합니다.

```text
게임이름#태그
```

예시:

```text
Hide on bush#KR1
```

따옴표는 입력하지 않습니다. 봇은 Riot Account API에서 Riot ID를 확인하고, KR 리전의 LoL 계정이 존재하면 현재 Discord 사용자와 연결합니다. 같은 서버에서 하나의 Riot 계정을 여러 Discord 사용자가 중복 등록할 수는 없습니다.

이 명령은 Discord 서버 소유자 또는 `서버 관리`/관리자 권한이 있는 운영자만 사용할 수 있습니다. 운영자가 다른 친구를 등록할 때는 `멤버` 옵션에서 대상을 선택합니다.

```text
/atoz 멤버등록 롤아이디:훈레사#KR1 멤버:@등록할친구
```

`멤버` 옵션을 생략하면 명령을 실행한 운영자 본인이 등록됩니다.

부캐(다른 Riot 계정)가 있다면 본캐를 먼저 등록한 뒤 아래 명령으로 연결할 수 있습니다. 부캐로 플레이한 경기도 전적 통계(티어픽/승률순위/조합추천)에서는 본캐 기준으로 합산됩니다.

```text
/atoz 부캐등록 부캐롤아이디:레사훈#KR1 본캐멤버:@훈레사
```

`본캐멤버`를 생략하면 명령을 실행한 운영자 본인의 본캐에 연결됩니다.

**잘못 등록했을 때:**
- 같은 사람을 다시 `/atoz 멤버등록`으로 등록하면 기존 Riot ID가 자동으로 새 값으로 덮어써집니다(별도 "수정" 명령 없이 재등록만 하면 됨).
- 아예 잘못된 Discord 멤버에게 등록됐다면 아래로 삭제 후 올바른 멤버로 다시 등록합니다.

```text
/atoz 멤버삭제 멤버:@잘못등록된사람
/atoz 부캐삭제 부캐롤아이디:레사훈#KR1
```

`/atoz 멤버삭제`는 연결된 부캐도 함께 삭제하지만, 이미 수집된 전적 기록(match_participations)은 남아 있습니다 — 재등록 후 `/atoz 전적수집`을 다시 돌리면 이어서 쌓입니다.

**등록 현황 확인:**

```text
/atoz 멤버목록
```

등록된 모든 본캐/부캐와 각 멤버의 수집된 경기 수를 보여줍니다. 잘못 등록됐는지(엉뚱한 Riot ID, 경기 수가 이상하게 0인 멤버 등) 확인할 때 씁니다.

등록 결과는 기본적으로 다음 위치의 SQLite 데이터베이스에 저장됩니다.

```text
%LOCALAPPDATA%\LolHelperBot\lol-helper.db
```

저장 위치를 바꾸려면 `Storage:DatabasePath` 설정 또는 `Storage__DatabasePath` 환경변수에 원하는 경로를 지정할 수 있습니다. 데이터베이스에는 Discord 사용자/서버 ID, 표시 이름, Riot ID, PUUID와 등록·수정 시각이 저장됩니다. API 키나 Discord 토큰은 저장하지 않습니다.

## 5. 클랜 전적 통계 (티어픽 / 승률순위 / 조합추천)

등록된 AtoZ 멤버들의 자유 랭크(5vs5 Flex, queue 440) 전적을 모아서 클랜 자체 통계를 보여주는 기능입니다. **같은 팀 5명 전원이 본캐/부캐 포함 등록된 AtoZ 멤버로 확인된 경기만** 저장합니다 — 매치메이킹으로 낯선 사람과 섞여서 플레이한 경기는 통계에 안 들어갑니다.

### 5-1. 데이터 수집 (운영자 전용)

```text
/atoz 전적수집 최근경기수:20
```

- 서버 소유자 또는 `서버 관리`/관리자 권한이 있는 운영자만 사용할 수 있습니다.
- 등록된 멤버(본캐+부캐) 전원의 최근 자유 랭크 경기를 Riot API로 조회하되, **같은 팀 5명 전원이 우리 멤버로 확인된 경기만** SQLite에 저장합니다. 일부만 우리 멤버인 경기(랜덤 매칭)는 저장하지 않습니다.
- **2026-08-01 이전 경기는 저장하지 않습니다**(2026-08-22부터, 데이터 정합성 확보를 위한 안전장치). `최근경기수`를 300처럼 크게 줘도 이 날짜보다 오래된 경기는 자동으로 걸러지고, 그 이전에 이미 저장된 데이터는 그대로 유지됩니다.
- 저장하지 않은 매치도 "확인 완료"로 기록해 두기 때문에, 다음 `/atoz 전적수집` 때 같은 매치를 Riot API로 또 조회하지 않습니다(API 호출 절약). **단, `/atoz 멤버등록`·`/atoz 부캐등록`으로 새 계정이 등록되면 이 "확인 완료(저장 안 됨)" 기록이 자동으로 초기화됩니다** — 예전엔 5명 미달이었던 매치가 새 멤버 덕분에 이제 채워질 수 있기 때문입니다.
- ⚠️ **부캐를 여러 명이 돌려쓰는 경우의 한계**: 부캐의 등록된 기본 소유자와 그 부캐를 실제로 플레이한 다른 사람이 **같은 경기에 동시에** 나오면(예: 기본 소유자가 본인 계정으로도 그 경기에 있었던 경우), 두 사람이 DB상 같은 discord_user_id로 겹쳐서 한쪽 기록이 저장 시 조용히 빠집니다(그 경기는 팀 인원이 5명이 아니라 4명으로 저장됨). 이런 경기는 `/atoz 전적수집` 결과 메시지에 "🔀 부캐 소유자 충돌" 경고로 표시되고, 충돌 상세 내역은 DB에 남습니다 — **`/atoz 부캐충돌목록`·`/atoz 부캐충돌해결`로 리플 파일 없이도 바로잡을 수 있습니다** (아래 5-1-1 참고).
- 저장할 때 우리 라이너와 **같은 라인의 상대 챔피언**(`opponent_champion_name`)도 함께 기록합니다 — `/밴픽추천`의 "주의 챔피언" 계산에 씁니다. `/atoz 전적수집`·`/atoz 부캐충돌해결` 저장 시점에 자동으로 채웁니다. 내전 리플은 별도 큐로 저장되어 자유 랭크 통계에 섞이지 않습니다.

#### 5-1-1. 부캐 소유자 충돌 확인/해결 (운영자 전용)

```text
/atoz 부캐충돌목록
/atoz 부캐충돌해결 매치아이디:KR_8286962111 롤아이디:반가워 나의 서폿#KR33 멤버:@실제로_플레이한_사람
```

- `/atoz 부캐충돌목록` — 아직 해결 안 된, **진짜로 누락된** 계정만 매치별로 보여줍니다. 충돌 그룹 중 이미 정상 저장된 쪽(PK 경쟁에서 "이긴" 쪽)은 손댈 필요가 없어서 자동으로 목록에서 빠집니다 — 실제로 데이터가 비어있는 쪽만 보이니, 뜨는 항목만 처리하면 됩니다. 매치ID, 기본 소유자, 충돌난 계정의 롤아이디·라인·챔피언이 나옵니다.
- `/atoz 부캐충돌해결` — 목록에서 확인한 매치ID + 롤아이디를 실제 디스코드 멤버로 지정하면, Riot API로 그 매치를 다시 조회해서 **그 계정의 그 경기 기록만** 정확한 사람 기준으로 저장합니다(다른 계정의 데이터는 전혀 건드리지 않습니다). 리플 파일이 필요 없습니다 — 매치ID만 있으면 Riot 서버에 원본 데이터가 남아있는 한 언제든 해결 가능합니다.
- 한 경기에 계정 3개 이상이 겹치는 경우처럼 누락된 사람이 여럿이면, `/atoz 부캐충돌목록`에 뜨는 각 항목마다 `/atoz 부캐충돌해결`을 한 번씩 실행하면 됩니다.
- `최근경기수`는 생략하면 20, 최대 300까지 지정할 수 있습니다. 100을 넘으면 내부적으로 여러 페이지를 나눠서 조회합니다(Riot API가 한 번에 최대 100경기까지만 주기 때문).
- ⚠️ **오래된 경기는 정기 수집만으로는 영영 못 잡을 수 있습니다.** 이 명령은 "각 계정의 최근 N경기"만 보는 구조라, 등록된 지 오래된 클랜원이 낀 매치가 시간이 지나 모든 계정 기준으로 "최근 N경기" 밖으로 밀려나면 그 뒤로는 아무리 재수집해도 잡히지 않습니다. 놓친 것 같으면 가끔 `최근경기수:300`처럼 크게 잡고 한 번씩 "딥 백필"을 돌리는 걸 권장합니다(계정 수·경기 수에 따라 몇 분~십몇 분 걸릴 수 있음).
- Riot API 요청 한도 때문에 멤버/매치 수가 많으면 수집에 몇 분 걸릴 수 있습니다. 정기적으로(예: 매주 한 번, 기본 `최근경기수`로) 실행해서 데이터를 쌓아가는 방식을 권장합니다.

#### 5-1-2. 부캐를 잠깐 빌려쓴 경기 재배정 (운영자 전용, 2026-08-22 추가)

```text
/atoz 전적재배정 매치아이디:KR_8348359834 기존멤버:@부캐_등록_주인 새멤버:@실제로_플레이한_사람
```

위 5-1-1(부캐 소유자 충돌)과는 다른 상황을 위한 명령입니다. 충돌은 "저장 자체가 씹혀서 데이터가
비어있는" 경우고, 이건 **저장은 정상적으로 됐지만 그 경기만 다른 사람이 부캐를 빌려서 한
경우**입니다. Riot API를 다시 조회하지 않고 이미 저장된 기록의 소유자만 그대로 옮깁니다. 대상
멤버가 이미 같은 경기 기록을 갖고 있으면(=진짜 부캐 충돌) 덮어쓰지 않고 거부하니, 그런 경우는
5-1-1을 대신 쓰세요. `/atoz 아재전적` 각 경기 카드 맨 아래에 작게 표시되는 매치ID를 그대로
복사해서 쓰면 됩니다.

**새 멤버를 등록할 때마다 롤 아이디를 일일이 물어보기 번거롭다면:**

```text
/atoz 전적등록후보 기준아이디:훈레사#KR1 최근경기수:50
```

이미 등록된 멤버(기준아이디)의 최근 자유 랭크 50경기를 훑어서, **같은 팀으로 자주 나온 미등록 계정**을 "몇 번 같이 했는지" 순으로 보여줍니다. 디스코드 계정과의 매칭은 자동으로 안 되니(Riot API는 디스코드 정보를 몰라요) 목록 보고 누구인지 확인한 다음 `/atoz 멤버등록`·`/atoz 부캐등록`으로 등록해 주세요. 매치 50개를 순차 조회하는 구조라 완료까지 1분 정도 걸릴 수 있습니다.

등록(특히 부캐 등록)을 마친 뒤에는 `/atoz 전적수집`을 한 번 더 실행하면, 그 시점에 등록된 계정 전체를 다시 훑기 때문에 새로 등록한 사람의 경기도 자동으로 수집됩니다 — 별도 명령이 필요 없습니다.

### 5-2. 조회 명령어 (전체 멤버 사용 가능)

```text
/티어픽 라인:미드
/밴픽추천 라인:미드
/승률순위
/내전적
/조합추천
/바텀듀오
/봇듀오챔프승률
/정글미드듀오챔프승률
/아재전적 개수:5
/명예의전당
/명예의전당 연월:2026-08
```

빠르게 훑어보고 싶다면 아래 표, 세부 동작(표시 형식·조건·아이콘 의미)은 표 아래 상세 설명을
참고하세요.

| 명령어 | 한 줄 요약 |
|---|---|
| `/티어픽 [라인]` | 라인별 챔피언 승률 TOP 5(+ 전체 워스트 5) |
| `/밴픽추천 [라인]` | 클랜 데이터 추천픽 + op.gg 메타픽 + 밴 후보 3종 |
| `/승률순위 [연월]` | 클랜원 전체 승률·KDA 순위 + 월간(이번 달) 순위 |
| `/내전적 [멤버] [월]` | 개인 총 승률·**최근 전적**·라인별 승률·모스트/워스트 챔피언 |
| `/조합추천` | 함께 나왔을 때 승률 좋은 챔피언 조합 TOP 10 |
| `/바텀듀오` | 원딜+서폿 **사람** 조합 승률 |
| `/봇듀오챔프승률` | 원딜+서폿 **챔피언** 조합 승률 |
| `/정글미드듀오챔프승률` | 정글+미드 **챔피언** 조합 승률 |
| `/아재전적 [개수]` | AtoZ 5인큐 경기 자체를 최근 순으로(기여도 순위 포함) |
| `/명예의전당 [연월]` | 그 달 기여도 베스트를 가장 많이 한 멤버 랭킹 |

- `/티어픽 [라인]` — 라인별로 우리 클랜 데이터 기준 승률 좋은 챔피언 TOP 5. 라인을 생략하면 전체 라인. 각 라인 1위엔 👑, **TOP5 전부(1~5위)** 그 챔피언을 실제로 플레이한 멤버를 **"이름 N판 · 승률X%"** 형식으로 괄호에 판수 많은 순으로 나열합니다(예: `(기 5판 · 승률80%, HoonJP 2판 · 승률50%)`). 맨 아래에는 라인 구분 없이 **전체 챔피언 중 승률 워스트 5개**(💀, 승률 50% 미만)도 별도 표시되고, 여기도 동일한 형식으로 플레이어별 내역이 붙습니다.
- `/밴픽추천 [라인]` — 라인을 생략하면 탑·정글·미드·원딜·서폿을 **각각 다른 색의 임베드**로 나눠 보여줍니다. 라인마다:
  - **우리팀 추천픽 Top 3**(우리 클랜 데이터 기준 승률 50% 이상) — 메타 OP~1티어와 겹치면 순위 아이콘 대신 `🐝`가 붙습니다. [메타 스냅샷](LolHelperBot/Config/MetaTierSnapshot.json)에 카운터 정보가 있으면 "메타 카운터: X, Y"도 표시합니다.
  - **메타픽 Top 3** — op.gg OP~1티어 후보를 `승률 50% 초과분×2 + 픽률 + 밴률`로 평가합니다. 메타 티어·승률·픽률·밴률과 함께 **AZ 자랭 판수·승률·메타 대비 승률 차이**, 해당 챔피언을 플레이한 모든 멤버를 `기(5판, 80%) · 정현(3판, 67%)` 형식으로 표시합니다. AZ 표본은 3판 이상부터 신뢰 표본으로 보고 `🐝`(승률 50% 이상), `⚠️`(50% 미만), `🧪`(3판 미만 또는 미플레이)로 구분합니다. 후보가 3개보다 적은 라인은 있는 만큼만 보여줍니다.
  - **밴 추천 최대 3개** — 서로 다른 근거로 각 1개씩(조건을 만족하는 후보가 없으면 억지로 채우지 않고 그만큼만 표시): (1) 💀 맞상대 승률 낮은 챔프(클랜 데이터), (2) 🔥 메타 티어 높은 챔프(op.gg 스냅샷 — 없으면 자동으로 건너뜀), (3) 🚨/⚠️ 우리 라인 Top3 베스트픽이 상대했을 때 유독 승률이 안 나온 챔프("우리 티어픽 카운터", 클랜 데이터).
  - **일반 메타(op.gg) 데이터는 자동 크롤링이 아니라 수동 스냅샷**으로 연동됩니다 — op.gg는 `robots.txt`상 크롤링을 막지는 않지만 ToS가 불확실해서, [Config/MetaTierSnapshot.json](LolHelperBot/Config/MetaTierSnapshot.json)을 사람이 주기적으로 채워넣는 방식을 택했습니다. 이 파일이 비어 있어도 클랜 데이터 기반 추천(픽 Top3, 밴 (1)·(3))은 그대로 동작합니다. **op.gg 화면을 캡처해서 [Config/OpggCaptures/](LolHelperBot/Config/OpggCaptures/)에 날짜별 폴더(`YYMMDD`, 예 `260820/`)로 넣어두면, Claude Code 세션에서 "최신 캡처 처리해줘"라고 요청해 캡처를 읽고 JSON을 갱신할 수 있습니다** — 뭘 캡처하면 되는지는 그 폴더의 README 참고. "밴 추천"은 참고 자료일 뿐이니 최종 판단은 사람이 해주세요.
- `/승률순위 [연월]` — 등록 멤버 전체의 자유 랭크 승률·KDA 순위(1/2/3위 👑/🥈/🥉), 그 아래에 **월간 승률 순위**(생략하면 이번 달, `2026-08` 형식으로 다른 달도 조회 가능, 2026-08-22 추가)를 별도 필드로 함께 보여줍니다. 두 순위 모두 최소 표본 기준을 적용하고 부족하면 전체로 폴백합니다.
- `/내전적 [멤버] [월]` — 지정한 멤버(생략 시 본인)의 우리 클랜 데이터 기준 **총 승률** 바로 아래에 **최근 N경기 서머리**(최근 최대 10경기 몇승몇패·승률, 모스트 픽 3개, 평균 AZ기여도 순위)와 **최근 전적**(최근 3경기 각각 승패·챔피언·KDA·기여도 순위, 2026-08-22 추가 — 이 두 섹션은 `월` 필터와 무관하게 항상 진짜 최신 경기 기준)을 보여준 뒤, **라인별 승률**(각 라인 옆에 그 라인에서 가장 많이 한 **모스트 챔피언 TOP 3**를 "챔프 N판 · 승률X%"로 같이 표시 — 이 라인별 모스트는 최소 표본 기준 없이 **판수(많이 한 순)**로 정렬합니다, 2026-08-21부터), **전체 모스트 챔피언 TOP 3**(승률 **50% 이상**, 최소 표본 기준 적용, 1/2/3위 👑/🥈/🥉), **전체 워스트 챔피언 TOP 3**(승률 **50% 미만**, 최소 표본 기준 적용, 1위만 💀)로 이어집니다. 해당하는 챔피언이 없으면 "없음"으로 표시됩니다. **`월`을 생략하면 전체 기간 통합**이고, `8`(8월만)/`8~8`(8월만)/`6~8`(6~8월) 형식으로 넣으면 이번 해(KST 기준) 해당 월(들)로만 필터링됩니다(라인별/모스트/워스트 통계에만 적용, 2026-08-21 추가).
- `/조합추천` — 같은 팀에서 함께 나왔을 때 승률이 좋은 **챔피언 조합**(듀오) TOP 10. 누가 픽했는지와 무관하게 챔피언 궁합만 봅니다. 1/2/3위는 👑/🥈/🥉 표시.
- `/바텀듀오` — **원딜+서폿 멤버 조합**(사람)의 승률을 모스트 10(승률 50% 이상, 1/2/3위 👑/🥈/🥉) / 워스트 10(승률 50% 미만, 1위만 💀)로 보여줍니다.
- `/봇듀오챔프승률` — **원딜+서폿 챔피언 조합**의 승률을 모스트 10(1/2/3위 👑/🥈/🥉) / 워스트 10(1위 💀)으로 보여줍니다. `/바텀듀오`가 "누구랑 누구"라면, 이건 "무슨 챔피언끼리"입니다.
- `/정글미드듀오챔프승률` — **정글+미드 챔피언 조합**의 승률을 모스트 10(1/2/3위 👑/🥈/🥉) / 워스트 10(1위 💀)으로 보여줍니다. `/조합추천`과 달리 정글+미드 라인 페어링으로만 한정합니다.
- `/아재전적 [개수]` — 앞의 명령들이 낸 "집계"가 아니라, **AtoZ 멤버 5명 전원이 한 팀으로 5인큐한 자유 랭크 경기 자체**를 최근 순으로 보여줍니다. `개수`는 기본 5, 최대 10경기이며 각 참가자 줄 끝에 그 판 기여도 순위도 표시됩니다.
- `/명예의전당 [연월]` — 지정한 달(생략하면 이번 달, KST 기준, `2026-08` 형식으로 다른 달도 조회 가능)에 **그 판의 기여도 1위(베스트)를 가장 많이 한 멤버 랭킹**을 보여줍니다(1위 1회당 100점, 워스트 횟수도 같이 표시). **월별 집계**라 지난달 순위와 무관하게 매달 새로 시작합니다(누적 아님). 기여도 점수를 계산할 수 없는 경기(`.rofl` 업로드로만 저장된 경기)는 집계에서 빠집니다.
- **기여도 점수(`/아재전적`, `/명예의전당`)**: 딜량·받은 피해량·골드·시야 점수·CC 시간·킬 관여율 등을 라인별로 다르게 가중치를 줘서, **같은 라인의 상대(맞라인)와 1:1로** 비교합니다(v3 — 정글은 상대 정글러랑만, 서폿은 상대 서폿이랑만 비교해서 라인 간 구조적 유불리를 없앰. 킬 관여율만 예외로 팀 5명 기준 그대로 사용). OP.GG의 "그 판 전체 절대 수치" 기준 랭킹과는 다른 지표라 항상 일치하진 않습니다(원딜/서폿에서 특히 갈리기 쉬움) — 가중치는 [ContributionScoreWeights.txt](LolHelperBot/Config/ContributionScoreWeights.txt)에 정의돼 있고 코드 수정 없이 숫자만 바꿔 튜닝합니다. `/atoz 전적수집`·`/atoz 부캐충돌해결`로 저장된 자유 랭크 경기만 이 지표가 있습니다.
- **표본이 5판 이하인 항목은 기본적으로 제외됩니다**(최소 6판 이상, 표본이 다 부족하면 예외적으로 전체를 보여줍니다). 소규모 클랜 특성상 판수가 적으면 통계가 튈 수 있어서 기준을 엄격하게 잡았습니다. (예외: `/내전적`의 **라인별 모스트 챔피언**은 그 라인 자체 판수가 이미 적은 경우가 많아 이 최소 표본 기준을 적용하지 않고, 판수를 항상 같이 표시해서 표본 크기를 직접 판단할 수 있게 했습니다.)
- **승률이 동률이면 판수가 많은 쪽이 위로 갑니다** (모든 승률 기준 순위·티어픽·조합/듀오 통계 공통 규칙).
- **"모스트/워스트" 계열 통계(`/내전적`, `/티어픽`, `/밴픽추천`, `/바텀듀오`, `/봇듀오챔프승률`, `/정글미드듀오챔프승률`)는 전부 승률 50%를 기준으로 나뉩니다** — 모스트(베스트 픽)는 승률 50% 이상만, 워스트(주의 챔피언)는 50% 미만만 후보로 삼습니다. 표본만 채웠다고 애매한 승률의 챔피언/조합이 섞이는 걸 막기 위함입니다.

### 5-3. 리플(.rofl) 파일로 내전 등록

```text
/atoz 리플업로드 리플파일:<.rofl 첨부>
/atoz 리플업로드 리플파일:<.rofl 첨부> 저장:true
/atoz 리플업로드 리플파일:<.rofl 첨부> 저장:true 재지정롤아이디:레사훈 재지정멤버:@메모리트리
```

- `.rofl` 리플레이 파일 안의 메타데이터를 직접 파싱해서 참가자 전적을 추출하며, 저장분은 **내전 전용 큐(queue 0)** 로 기록합니다. 자유 랭크(queue 440) 통계에는 섞이지 않습니다.
- **같은 팀 5명 전원이 우리 멤버로 확인돼야만** 저장됩니다. 미리보기 임베드의 "저장 대상" 필드에서 몇 개 팀이 저장 가능한지 확인할 수 있고, 1명이라도 매칭이 안 되면 그 팀은 저장되지 않습니다 — 이럴 때 아래 재지정 옵션으로 매칭을 채우면 저장 가능해집니다.
- **부캐를 여러 명이 돌려쓰는 경우**를 위한 재지정 옵션: `재지정롤아이디`(리플 속 게임이름 또는 게임이름#태그)와 `재지정멤버`를 함께 지정하면, `member_alt_accounts`에 등록된 기본 소유자와 상관없이 **이번 업로드 한 건에 한해서만** 그 계정의 기록을 지정한 멤버 데이터로 저장합니다. (예: "레사훈" 계정이 평소엔 훈레사의 부캐로 등록돼 있어도, 이 리플에서는 메모리트리가 대신 플레이했다면 `재지정롤아이디:레사훈 재지정멤버:@메모리트리`로 이 판만 메모리트리 기록으로 넣을 수 있음)
- **기본값은 미리보기만** — 실제로 DB에 저장하려면 `저장:true`를 함께 지정해야 합니다. 명령 자체가 운영자 전용입니다.
- ⚠️ `.rofl`은 라이엇이 공식적으로 문서화한 포맷이 아니라 커뮤니티가 역공학한 구조를 기준으로 파싱합니다. 클라이언트 버전에 따라 필드가 다를 수 있어 파싱이 실패할 수 있습니다 — 실패하면 알려주시면 파싱 로직을 조정하겠습니다.
- 리플 메타데이터 자체에는 Riot 공식 매치ID가 없지만, **파일명을 바꾸지 않았다면** 클라이언트 기본 파일명(`지역-게임ID.rofl`, 예: `KR1-1234567890.rofl`)에서 매치ID를 추정해서 사용합니다. 미리보기 임베드의 "매치ID" 필드에서 파일명 기반으로 추정됐는지, 아니면 리플 내용 기반 대체 ID를 썼는지 확인할 수 있습니다.
- 파일명 기반 추정이 실패하면(파일명을 바꿨거나 형식이 다르면) 경기 길이+참가자 기록 기반 해시 ID로 대체합니다. 같은 리플을 다시 올려도 같은 ID가 생성되어 내전 데이터 내 중복 저장을 막습니다.
- 리플 파일은 보통 20~60MB 이상이라 디스코드 서버의 파일 업로드 용량 제한(서버 부스트 레벨에 따라 다름)에 걸릴 수 있습니다. 업로드가 안 되면 서버 부스트 상태를 확인해 주세요.

## 6. 권한 구조 & 기능 안내

일반 멤버는 **조회(읽기)** 명령만 쓸 수 있고, 데이터를 등록·삭제·수집하는 명령은 **서버 소유자 또는 `서버 관리`/관리자 권한이 있는 운영자만** 쓸 수 있습니다.

| 구분 | 명령어 |
|---|---|
| 조회 (전체 멤버) | `/ping`, `/riotcheck`, `/티어픽`, `/밴픽추천`, `/승률순위`, `/내전적`, `/조합추천`, `/바텀듀오`, `/봇듀오챔프승률`, `/정글미드듀오챔프승률`, `/아재전적`, `/명예의전당` |
| 운영자 전용 (등록·삭제·수집) | `/atoz 멤버등록`, `/atoz 부캐등록`, `/atoz 멤버목록`, `/atoz 멤버삭제`, `/atoz 부캐삭제`, `/atoz 전적수집`, `/atoz 전적등록후보`, `/atoz 부캐충돌목록`, `/atoz 부캐충돌해결`, `/atoz 전적재배정`, `/atoz 리플업로드` |

`/atoz 멤버목록`은 등록된 모든 멤버의 실명·Riot ID 매핑이 다 보이기 때문에, 조회성 명령이지만 의도적으로 운영자 전용으로 묶어뒀습니다.

일반 멤버가 지금 뭘 쓸 수 있는지 헷갈려하면 아래 명령을 안내해주세요.

```text
/기능안내
```

조회 명령어 목록을 정리해서 보여줍니다(본인에게만 보이는 ephemeral 메시지). 내용은 이 README의 5장을 기준으로 합니다 — 새 조회 명령을 추가하면 [HelpModule.cs](LolHelperBot/Modules/HelpModule.cs)도 같이 업데이트해야 최신 상태로 유지됩니다.

## 7. Visual Studio 2026에서 실행하고 싶다면

`LolHelperBot.sln`을 열고 F5로 실행하면 됩니다. user-secrets는 `dotnet user-secrets` CLI로 미리 설정해두면 Visual Studio에서도 동일하게 읽힙니다(프로젝트 우클릭 → "사용자 암호 관리"로도 편집 가능).
